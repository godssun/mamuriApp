## 1. 리빌드 요약

### 현재 → 목표 전환

| 현재 (v2) | 목표 (v3) |
|-----------|-----------|
| 텍스트 일기 + AI 코멘트 | 스티커/비주얼 기반 감정 기록 + 사진 일기 + 꾸미기 + AI 컴패니언 |
| "쓰면 AI가 답한다" | "스티커 하나로 감정을 남기면, 마무리가 기억하며 함께 성장한다" |
| 텍스트 입력이 유일한 기록 수단 | 스티커 1탭 = 기록 완성 (텍스트 선택) |
| 회색 dot 캘린더 | 감정 스티커가 채워지는 감정 지도 |
| AI = 코멘트 기계 | AI = 맥락을 기억하는 컴패니언 |
| 리포트 = 숫자/차트 | 리포트 = AI 해석 중심 서사 |

### 핵심 전환 공식

```
기록 최소 단위: "텍스트 입력" → "스티커 1탭"
↓
캘린더 시각적 보상 (스티커가 쌓임)
↓
AI 컴패니언이 패턴을 기억하고 응답
↓
주간/월간 리포트로 감정 서사 제공
↓
"나의 감정 역사"가 쌓이는 제품
```

## 2. 유지 / 제거 / 재구축 대상

### 유지 (그대로 사용)

| 항목 | 이유 |
|------|------|
| JWT 인증 + 소셜 로그인 | 안정적, 재사용 가능 |
| AI 코멘트 생성 파이프라인 | PromptBuilder + 톤 분기 완성도 높음 |
| Safety check (위기 감지) | 핵심 안전 기능 — 반드시 유지 |
| Subscription 티어 구조 | FREE/TRIAL/PREMIUM 모델 그대로 |
| Spring Boot 도메인 분리 | user/diary/ai/global 아키텍처 적합 |
| 대화 시스템 (ConversationService) | 기존 로직 재사용 |
| 푸시 알림 인프라 | Expo Push 구조 유지 |

### 제거 (v3에서 없앰)

| 항목 | 이유 |
|------|------|
| 텍스트 기반 mood pill 버튼 | 스티커 그리드로 완전 대체 |
| 순수 dot 캘린더 | 감정 스티커 캘린더로 대체 |
| 톤 텍스트 선택 (warm/calm/cheerful/realistic) | 관계 단계가 톤을 자동 결정 |
| 이모지 8개 mood picker | EmotionPickerScreenV3으로 대체 |

### 재구축 (크게 변경)

| 항목 | 현재 → 변경 |
|------|------------|
| HomeScreenV2 | → HomeStickerScreenV3 (스티커 그리드 + 컴패니언 그리팅) |
| DiaryWriteScreenV2 | → DiaryExpressiveEditorV3 (사진+스티커+테마+꾸미기) |
| DiaryDetailScreenV2 | → DiaryPageDetailV3 (아름다운 저장 페이지) |
| ReflectScreenV2 | → EmotionCalendarV3 + ReflectionStoryV3 |
| CompanionScreenV2 | → CompanionChatV3 (관계 성장 중심) |
| DiaryEmotion 모델 | string → sticker_id 연결 (Additive) |
| 기억 시스템 | regex 3패턴 → LLM + 3계층 (단기/중기/장기) |
| 관계 모델 | 5단계 양적 → 7단계 양적+질적 |
| 프롬프트 | v5 → v6 (멀티모달 컨텍스트) |
| 캘린더 API | 날짜 목록 → CalendarDayEntry (스티커 포함) |
| Diary 엔티티 | content NOT NULL → nullable (비주얼 일기) |

## 3. 제품 방향 핵심 결정

### 3.1 감정 카테고리 구조 (2-Tier)

**Tier 1 — 기본 감정 5종 (스티커)**

| Key | 한국어 | 색상 | 스티커 컨셉 |
|-----|--------|------|------------|
| JOY | 좋아요 | #FFD166 | 밝게 웃는 해 캐릭터 |
| CALM | 괜찮아요 | #83C9A8 | 잔잔한 잎/달 캐릭터 |
| SAD | 별로예요 | #7BA7D9 | 조용한 물방울 캐릭터 |
| ANXIOUS | 힘들어요 | #E8A87C | 흔들리는 불꽃 캐릭터 |
| COMPLEX | 복잡해요 | #B8B0C8 | 소용돌이 별 캐릭터 |

**Tier 2 — 세부 감정 태그 30종 (텍스트 칩)**

### 3.2 일기 작성 흐름 (핵심 루프)

```
Step 1: 감정 스티커 선택 (필수, 1탭) — 10초
Step 2: 사진 첨부 (선택, 0-3장)
Step 3: 텍스트 기록 (선택)
Step 4: 꾸미기 — 데코 스티커 + 테마 (선택)
Step 5: 저장 → AI 응답 + 캘린더 반영
```

### 3.3 기록 단계별 인정

| 단계 | 소요 | 포함 내용 | 인정 |
|------|------|----------|------|
| Level 0 | 10초 | 스티커만 | 스트릭 유지 ✅ |
| Level 1 | 30초 | 스티커 + 한 줄 | AI 개인화 응답 ✅ |
| Level 2 | 2분 | 스티커 + 사진 + 텍스트 | AI 풍부한 리플렉션 ✅ |
| Level 3 | 5분+ | 전체 + 꾸미기 | 프리미엄 기록 ✅ |

### 3.4 컴패니언 관계 7단계

| 단계 | 이름 | 핵심 AI 행동 변화 |
|------|------|------------------|
| 1 | 첫 만남 | 공손, 일반적 공감 |
| 2 | 알아가는 중 | 이전 일기 가볍게 언급 |
| 3 | 관심과 기억 | 기억 적극 활용, 패턴 언급 시작 |
| 4 | 편안한 친구 | 가벼운 유머, 패턴 지적 가능 |
| 5 | 깊은 신뢰 | 진심 어린 조언, 성장 비교 |
| 6 | 든든한 동반자 | 장기 서사 연결 |
| 7 | 소울메이트 | 완전한 맥락 이해, 기념일 인식 |

### 3.5 기억 시스템 3계층

| 계층 | 유지 기간 | 내용 | decay |
|------|----------|------|-------|
| 단기 | 7일 | 최근 일기 요약, 대화 키포인트 | 자동 삭제/승격 |
| 중기 | 2~4주 | 주간 감정 패턴, 진행 중 이벤트 | 4주 후 아카이브 |
| 장기 | 영구 | 성격, 핵심 관계, 인생 이벤트 | 없음 |

## 4. UI 방향 핵심 결정

### 4.1 스티커 비주얼 스타일 — "따뜻한 미니멀리즘"

- 플랫 2D, 라운드 형태, 그림자 없음
- 2~3색만 사용 (배경색 + 포인트색 + 라인색)
- 128×128px 투명 PNG (기본 크기)
- 귀엽되 유치하지 않은 톤

### 4.2 데코 스티커 배치 방식

자유 드래그 없음. **고정 위치 프리셋 3개** (React Native 구현 현실성):
- top-left / top-right / bottom-right

### 4.3 일기 테마 4종

| 테마 | 배경 | 느낌 |
|------|------|------|
| 기본 | 흰 배경 | 깔끔 |
| 노트 | 연황색 + 줄무늬 | 따뜻한 노트 |
| 야간 | 다크 + 별 | 밤의 고요함 |
| 꽃잎 | 연분홍 + 원형 데코 | 부드러운 봄 |

### 4.4 에셋 전략 — 정적 큐레이션 (MVP)

```
mobile/assets/stickers/
├── emotion/ (5개 감정 스티커, @1x/@2x/@3x)
└── deco/
    ├── mood/ (12개 기본 무드)
    ├── daily/ (16개 일상 — Post-MVP)
    ├── season/ (16개 계절 — Post-MVP)
    ├── cheer/ (12개 격려 — Post-MVP)
    └── text/ (8개 텍스트 — Post-MVP)
```

MVP: 감정 5개 + 데코 무드 12개 = **17개 에셋 우선 제작**

## 5. 데이터/백엔드 핵심 결정

### 5.1 DB 마이그레이션 순서

```
V23: 감정 스티커 카탈로그 + diary_emotions 컬럼 추가 + diaries 확장
V24: diary_photos + decoration_assets + diary_decorations
V25: emotion_statistics + 시드 데이터
```

### 5.2 Diary 엔티티 확장

```sql
ALTER TABLE diaries
  ALTER COLUMN content DROP NOT NULL,          -- 비주얼 일기 지원
  ADD COLUMN diary_type VARCHAR(20) DEFAULT 'TEXT',  -- TEXT/VISUAL/MIXED
  ADD COLUMN cover_photo_id BIGINT,
  ADD COLUMN background_asset_id BIGINT;
```

### 5.3 핵심 신규 테이블

| 테이블 | 용도 |
|--------|------|
| emotion_categories | 감정 카테고리 (5종) |
| emotion_stickers | 감정 스티커 에셋 카탈로그 |
| diary_photos | 사진 첨부 (일기당 최대 3장 FREE / 10장 PREMIUM) |
| decoration_assets | 꾸미기 에셋 카탈로그 |
| diary_decorations | 일기 내 꾸미기 배치 (상대 좌표 0.0~1.0) |
| emotion_statistics | 감정 패턴 집계 (월별 캐시) |

### 5.4 캘린더 API 확장

```
GET /api/diaries/calendar?year=&month=&v=2

응답: CalendarDayEntry[]
{
  date, diaryCount, primaryStickerUrl, primaryEmotionCode, emotionScore
}
```

### 5.5 저장 전략

- MVP: LocalStorageService (서버 경유 업로드)
- 전환: StorageService 인터페이스 추상화 → S3StorageService
- 스티커: 앱 번들 내 포함 (CDN 불필요)

## 7. 안전한 개발 전략

### 7.1 기존 데이터 보존 원칙

- **Additive 전략**: 기존 컬럼 삭제 없음. 새 컬럼만 추가.
- `diary_emotions.primary_emotion` (VARCHAR) 유지 + `primary_sticker_id` 추가
- `diaries.content` NOT NULL → nullable 변경 (기존 데이터는 이미 값 있음)
- 기존 감정 코드 → 스티커 매핑 스크립트로 데이터 연결

### 7.2 화면 전환 전략

- v2 화면 즉시 삭제하지 않음
- v3 화면을 별도 파일로 생성 → 네비게이션에서 교체
- Feature flag로 v2/v3 전환 가능하게 (위험 관리)

### 7.3 하지 말아야 할 것

- 좌표를 픽셀로 저장하지 말 것 (0.0~1.0 상대값 필수)
- 스티커 카탈로그를 앱 하드코딩하지 말 것 (DB 관리)
- 사진 업로드를 일기 저장 트랜잭션에 포함하지 말 것 (별도 API)
- 기존 데이터를 마이그레이션 없이 삭제하지 말 것
